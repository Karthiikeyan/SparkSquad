# Decisions

Product-owner decisions (fixed). Append your own below with one line of reasoning each.

| # | Decision | Why |
|---|---|---|
| D1 | App name **SparkSquad**, a SparkTribe product. Bundle ID / package `com.sparktribe.sparksquad`, URL scheme `sparksquad://`. | Ties to the SparkTribe audience; no existing app with this name found in the stores (Oct 2026). |
| D2 | Backend: **Cloudflare Workers + D1 + R2 + Better Auth** (not Supabase). | ₹0 for longer, no egress fees, built-in point-in-time restore. Fallback only if a blocking issue appears: Supabase (record why here first). |
| D3 | Payments: build the full RevenueCat flow, ship the pilot with `PAYMENTS_ENABLED=false`. | Lets the pilot run without store products or RevenueCat setup; turning on payments is a config change, not a rebuild. |
| D4 | Admin: protected `/v1/admin/*` endpoints + a minimal static `/admin` page served by the Worker. No separate admin app. | Enough to meet the 24-hour report-review promise with almost no extra code. |
| D5 | Invite links: `sparksquad://join/CODE` plus `https://<api-domain>/join/CODE` redirect pages until a custom domain is bought; then add universal/app links. | Works on day one without buying a domain. |
| D6 | Dark theme is the default; light theme tokens exist but ship later. | Matches the reference designs; halves design QA for v1. |
| D7 | Users must be 18+. | Avoids DPDP verifiable-parental-consent obligations for minors. |

## Engineering decisions (append below)

| # | Decision | Why |
|---|---|---|
| E1 | Build kit moved from `sparksquad-build-kit/` to the repo root. | The kit's own instructions expect `docs/`, `design/`, `.github/` at the root; all doc paths assume it. |
| E2 | pnpm 12 with `nodeLinker: hoisted` (set in `pnpm-workspace.yaml`). | Metro and many React Native native modules still assume a flat `node_modules`. |
| E3 | TypeScript pinned to `~6.0` (not 7). | `typescript-eslint` supports `<6.1`; TS 7 (native port) would break linting. |
| E4 | Vitest 5 everywhere; Workers tests use `@cloudflare/vitest-plugin` (renamed from `@cloudflare/vitest-pool-workers`). | The old package is deprecated; the plugin is the same API. |
| E5 | NativeWind 4.2 + Tailwind 3.4 (not NativeWind 5 RC). | Latest stable; v5 is still a release candidate. |
| E6 | Expo Router routes live in `apps/mobile/app/` (not the template's `src/app/`). | Matches Architecture §2. |
| E7 | Colour tokens live in `apps/mobile/src/theme/colors.js` (CommonJS). | One source for both `tailwind.config.js` and typed `theme.ts`. |
| E8 | Prettier `endOfLine: auto`, `.gitattributes` normalises to LF in git. | Windows checkouts keep CRLF locally without failing the format check; the repo stays LF. |
| E10 | `planHash` uses a small pure-TS SHA-256 instead of `crypto.subtle`. | Must be synchronous and identical on Hermes (no WebCrypto digest), Node and Workers. |
| E11 | Added `json5` to `packages/shared`. | Plan Format §2 asks for a forgiving parser fallback (unquoted keys, single quotes); tiny, no deps. |
| E12 | Partial check-in counts as done only when `partialCounts` is on **and** ≥50% of tasks are met. | Spec says "default true for ≥50% tasks"; threshold lives in `scoring.ts`. |
| E13 | Streak freezes are only spent when there is a streak to protect; rest days never touch streaks; a tier downgrade trims banked freezes to the new cap. | Avoids wasting freezes and keeps limits honest. |
| E14 | Leaderboard ranks by exact done/elapsed ratio, then tasks done; exact ties share a rank (1, 1, 3). | Rounded % would create false ties; competition ranking is the familiar convention. |
| E15 | Check-in window: accept local dates from (local date of now−14 h) − 1 day up to local date of now+14 h. | Implements "today or yesterday ±14 h for travel" (Architecture §7) in one rule. |
| E16 | Templates are generated by `templates/build.mjs` and committed as JSON. | Keeps 200+ days of content consistent and easy to edit; JSON stays the source the API seeds from. |
| E17 | Steps template uses an "easy day" (6,000 steps) instead of a rest day each week. | One task a day as specified, while keeping a weekly lighter day. |
| E18 | Missing days in an imported plan become rest days titled "Open day". | Plan Format says empty days are treated as rest; keeps streaks fair. |
| E19 | `challenges` stores `rest_days` and `task_counts` JSON (beyond Architecture §3). | Streak and leaderboard maths need rest days for every member without reading the plan from R2. |
| E20 | Streaks are recomputed by replaying a member's check-ins (≤120 days per challenge, ≤400 days global) on each check-in and at local 01:00. | Backfilling yesterday automatically refunds a freeze; no fragile incremental state. |
| E21 | Members count from the challenge start if they were in the squad when it was created (or checked in earlier), else from their join date; today counts only once checked in. | Fair consistency for late joiners and no mid-day penalty. |
| E22 | "Challenge complete" badge needs ≥80% consistency at the end. | Spec doesn't define it; 80% rewards finishing without demanding perfection. |
| E23 | Join requests, approvals, announcements, milestones go to the inbox and the 09:00 digest push; only nudges push immediately. | Architecture §5.4 (nudges are the only immediate push; max 2 digests/day). |
| E24 | Declined join requests are deleted (can ask again); removed members cannot rejoin a public squad by id. | Avoids harassment loops while letting honest mistakes be fixed. |
| E25 | Personal targets are sent with each check-in (`targets`) and honoured only when the squad allows them; they live on the phone. | Data model has no column for them; keeps server state minimal. |
| E26 | R2 access: S3 presigned URLs when `R2_*` API credentials exist, otherwise HMAC-signed Worker URLs (`/files/*`). | Works in local dev and without extra credentials; same client code. |
| E27 | Deleting an account hands owned squads to the longest-standing admin (else member); squads with nobody left are deleted. | Spec asks for an owner-transfer warning; this avoids orphaned squads. |
| E28 | Deleted squads are archived (`archived_at`) and delivered via sync as `removedSquadIds`. | Phones learn about deletions through delta sync. |
| E29 | Squad Pro purchases carry the squad id as a RevenueCat subscriber attribute `squad_id`. | Webhooks need to know which squad becomes Pro. |
| E30 | Seeding uses `wrangler r2 object put` + `wrangler d1 execute` from a Node script. | Works for local and remote with the same credentials as deploys; no admin endpoint needed. |
| E9 | API tests call `app.request(path, init, env)` with `env` from `cloudflare:workers`. | Fully typed without generating `wrangler types`; still runs inside workerd. |
| E31 | Mobile UI components use `StyleSheet` + typed tokens (`src/theme/tokens.ts`); NativeWind stays available for screen layout. | Exact design values with type checking; components are easy to test. |
| E32 | Extra neutral tokens taken from the designs: `strong #48484D`, `onControl #D6D6DB`, `chipLabel #C7C7CC`, `avatarLabel #E6E6EA`, `heatEmpty #26262A`, `scrim`. | The reference screens use them (grabber, stepper glyphs, chips, heatmap) but the token table doesn't name them. |
| E33 | Local SQLite migrations are hand-written, append-only SQL in `src/lib/db/migrations.ts`; version stored in the `kv` table. | No babel inline-import of `.sql` files, and the same migrator runs on device and in Node tests. |
| E34 | Screens read SQLite through TanStack Query keys under `['local', …]`, invalidated on `syncCompleted` / `outboxChanged`. | One cache model for local and remote reads; no live-query listeners. |
| E35 | The sync cursor lives in SQLite `kv`, written in the same transaction as the data (not MMKV). | Cursor and data can never diverge after a crash. |
| E36 | Outbox is strict FIFO. Network/429/5xx back off 5 s → 10 min and hold later writes; 4xx marks the item failed and reverts optimistic state by refetching the check-in (or unpins it for the next sync if offline). A timer retries the head item when its backoff ends. Check-in, fire and nudge writes coalesce per entity; comments never do. | Keeps write order intact; never retries writes the server rejected. |
| E37 | Locally, other members' check-ins are kept 14 days, mine indefinitely, notifications 30 days; blocked users' rows are purged on sync. | Small store, history for me, blocks honoured offline. |
| E38 | Mobile store tests run real SQL with Node's built-in `node:sqlite` behind Drizzle's `sqlite-proxy` driver. | Exercises the real queries without a native build. |
| E39 | Added `expo-crypto` to polyfill `crypto.getRandomValues`. | Shared ULID/invite helpers need it and Hermes may not provide it. |
| E40 | Fonts are imported from per-weight subpaths (`@expo-google-fonts/inter/400Regular`). | The package index bundles every weight (~10 MB). |
| E41 | Validation errors use label-coloured text with an accent alert icon, never red. | Red is reserved for destructive actions; the icon means colour isn't the only signal. |
| E42 | `TabBar` is presentational; `app/(tabs)/_layout.tsx` adapts Expo Router's vendored tab bar props (`emitter`, `navigateToTab`). | Expo Router 58 vendors react-navigation; keeps the component testable. |
| E43 | Analytics drops sensitive property names and key-shaped values; Sentry drops request headers/cookies/body and fetch/xhr breadcrumbs. | BYOK keys and auth must never reach analytics or crash reports. |
| E44 | `@sentry/cli` may run its postinstall (`allowBuilds`). | Needed for source-map upload on EAS builds. |
| E45 | Numbers in copy use `en-IN` grouping (10,000 / 1,00,000). | Primary audience is in India. |
| E46 | The centre tab opens `checkin/[challengeId]` with `next`, a transparent modal hosting `BottomSheet`. | Phase 5 resolves `next` to the first pending challenge; the picker lives in the sheet (B4). |
| E47 | RNTL 14 is async (`await render`, `await fireEvent.press`); TS 6 defaults `types` to `[]`, so the mobile tsconfig lists `jest` and `node`. | Tooling behaviour of the pinned versions. |
| E48 | Auth/onboarding routing uses `Stack.Protected` groups (signed out → `(auth)`, signed in but not onboarded → `(onboarding)`, ready → app) plus one pure `resolveRoute()` in `app/index.tsx`. | Guards can't be bypassed by deep links; one tested function decides every redirect. |
| E49 | "Onboarded" = server consent + username **and** a per-user local flag (`onboardedUserId`). Returning users whose profile is already complete skip onboarding automatically. | Saving the username mid-flow must not eject the user before A7–A10; reinstalls shouldn't repeat onboarding. |
| E50 | Native Google sign-in (`@react-native-google-signin/google-signin`) and Apple (`expo-apple-authentication`) send ID tokens to Better Auth (`signIn.social({ idToken })`); Apple uses a raw nonce. Buttons show only when `/v1/config` enables the provider and the build has the client ids (iOS also needs `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`). | Architecture §4 asks for ID-token sign-in from native; hiding unconfigured providers avoids dead buttons. |
| E51 | Sync and outbox delivery only run while signed in (`setSignedIn`); a 401 from our API signs out, unregisters the push token, wipes local data and analytics identity. A different user signing in wipes the previous user's local store. | Avoids 401 loops and data leaking across accounts on a shared phone. |
| E52 | Invite deep links (`sparksquad://join/CODE`) work signed out: the code is kept in MMKV (`pendingInvite`), survives sign-in/onboarding (A9 then skips A10), and opens `invite/[code]`. | Spec: "Deep-link invite skips A10 straight to Squad preview". |
| E53 | Squad preview (E3) and Join with code (E4) were built in Phase 4. | Invite deep links need a working landing screen; Phase 7 reuses them. |
| E54 | Consent (A5) uses two checkboxes (18+, terms) because the API requires both flags; Terms and Privacy ship as in-app pages (`settings/legal/[doc]`) reachable signed out. | Consent must be explicit and the documents readable before agreeing. |
| E55 | OTP entry is one hidden `TextInput` (one-time-code autofill, paste) under six visual boxes. | Paste and autofill work reliably; screen readers get one field. |
| E56 | Reminder time picker: iOS inline spinner, Android system clock dialog (`@react-native-community/datetimepicker`). Scheduling the local reminder is Phase 5. | Native pickers on each platform; one well-maintained dependency. |
| E57 | Push token registration happens after the A9 permission grant and on each signed-in launch when permission exists; it needs `EAS_PROJECT_ID`. | Expo push tokens require the EAS project id; missing id just skips registration. |
| E58 | Jest setup mocks MMKV (in-memory), Sentry, PostHog, NetInfo and safe-area globally; route screens are tested from `src/**/__tests__` (never under `app/`). | Native modules don't exist in Jest; tests under `app/` would become routes. |
| E59 | Plans are cached in SQLite by plan hash and downloaded after each sync (`ensurePlans`); unused hashes are dropped. Day edits overlay the cached plan on the phone. | Plans are immutable per hash, so each is fetched once; Today works offline. |
| E60 | Today is a pure function of local data (`buildTodayCards`). Members' ring uses the viewer's local date; honest misses count as showing up on the ring. | One tested place for card states; Product Spec counts honest misses as engagement. |
| E61 | Ticks on the Today card are a phone-only draft (MMKV, per challenge + date) that pre-fills the check-in sheet; nothing reaches the server until "Check in". | Matches the design (ticks + "Check in (1 of 3 done)") without extra writes. |
| E62 | The phone computes status (shared `computeCheckinStatus`) for optimistic UI and the success screen; the server's answer replaces it. Edits reuse the day's check-in id. | Instant feedback offline; server stays authoritative; idempotent upserts. |
| E63 | Success screen streak is predicted locally (`predictedStreak`) and new badges appear when the outbox writes the server's answer. | The celebration can't wait for the network. |
| E64 | Free photo proof is copied into app storage (`documents/proofs`) and only `hasPhoto` is sent. Plus photo upload is deferred to the billing phase. | Product Spec: free photos never leave the phone; Plus can't be bought in the pilot. |
| E65 | Local reminders are one-off DATE notifications for the next 7 days at the reminder time, re-planned after every sync/outbox change: today's is skipped once all challenges are checked in, and a morning note (08:00) is planned while today is open. | Daily repeating triggers can't skip a day; re-planning keeps reminders honest with no server pushes. |
| E66 | Push taps route by `data.type` (`inbox` → inbox, everything else → Today); any received push triggers a refresh. Squad-specific routes arrive with the squad screens. | Architecture §5.1: boards refresh when a push arrives. |
| E67 | The B6 freeze sheet shows the unread `freeze_used` notification created today, once per day (MMKV `lastFreezeNoticeDate`), then marks it read. | Spec: "shown once next morning". |
| E68 | The Better Auth client is mocked globally in Jest. | It is ESM-only and networked; no unit test signs in. |
| E69 | Board, Leaderboard and Plan are segments of one `squad/[id]` screen; `squad/[id]/leaderboard` and `/plan` redirect with `?tab=`. | One header and data load; deep links still work. |
| E70 | Board data comes from the local store; leaderboard, members, requests, history and comments are live API reads (TanStack Query cache) because they aren't part of delta sync. | Keeps sync small; these screens are online-first by nature. |
| E71 | Fire reactions and nudges are optimistic local writes plus outbox items; comments post directly and fall back to the outbox when offline. Squad admin actions (roles, requests, settings, announcement, transfer, end, delete, leave) call the API, then trigger a sync. | Daily-loop actions must work offline; admin actions need an immediate answer. |
| E72 | "Longest streaks" on the share card and a member's run are computed on the phone from locally synced check-ins (others: 14 days), skipping plan rest days; honest misses don't extend a run. | The API exposes only my streaks; a 14-day window is enough for a daily card. |
| E73 | Plan strip days before the synced range show as neutral `past` (no dot), never as missed. | We don't know about them; never shame (Product Spec §1). |
| E74 | "Share to WhatsApp" opens the system share sheet with the PNG (react-native-view-shot); "Save image" uses `expo-media-library/legacy` write-only permission. | Apps can't target WhatsApp with an image directly; write-only permission asks for the least. |
| E75 | Invite links are `${EXPO_PUBLIC_API_URL}/join/CODE` (the API landing page) and the QR code encodes that link. | D5: works without a custom domain. |
| E76 | Plan export shares a `.json` file written to the cache with the shared `exportPlan` (edits included), not the API export endpoint. | Works offline and matches the canonical file format. |
| E77 | My squads shows "Requests to join" only for private squads I manage, fetched per squad while online. | Public squads have no requests; avoids calls for members. |
